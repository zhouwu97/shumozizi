# 科学事实生命周期：最小修复方案

## 判断

“工作流全面失效审计”的核心判断成立：历史流程把“命令成功执行”“结论仍然
科学有效”“当前被选为正式答案”压在一个 `current` 状态中，又允许模型级红队
发现仅靠文字或一项局部结果关闭。这会造成红队已经推翻结论，而旧结果、图表、
Excel 和论文仍继续被消费。

不采用为每一种失败新增专用 JSON 和 hard gate 的做法。大量门禁会增加自报字段，
却不会增加科学证据。工作流只保留以下四个通用机制。

## 四个机制

### 1. 三类状态正交

每项结果分别记录：

- `execution_valid`：命令、输出和指标来源是否真实成功；历史事实不可因后续反例改写。
- `scientific_status`：当前科学结论是 `valid`、`conditional`、`invalidated` 或 `unresolved`。
- `selection_status`：结果是 incumbent、candidate、dominated 或 diagnostic。

`status=current` 仅保留为兼容入口。论文、提交工作簿和正式比较必须同时要求
执行有效、科学未失效且仍为 current。

### 2. 一条负证据级联

反例、独立复算冲突、不可行、性质测试失败、搜索挑战发现更优解，以及开放的
`MODEL_REPAIR` / `OBJECTIVE_REDESIGN` / `ANSWER_REJECTION` finding，全都进入同一
后果处理器。处理器一次性：

1. 标记受影响结果科学失效并退出 current；
2. 失效依赖结果的 current 图和关键主张；
3. 撤销编译/审核资格；
4. 回退到 analysis 或 experiment 主链。

不复制或删除原文件；消费者依据生命周期状态拒绝旧产物。这样保留可追溯历史，
也避免“删除不彻底”和多份索引漂移。

### 3. 修复按证据角色验收

简单文字、版式修复仍可用一条确定性检查关闭。会改变科学答案的修复必须绑定
指令打开后产生的 current production 结果。

若 finding 同时要求正式目标、独立复算、敏感性或导出等多个部分，只声明少量
`acceptance_roles`，关闭时逐角色绑定不同结果。工作流不引入通用谓词语言，也
不要求所有修复填复杂矩阵；角色只在多部分 P0/P1 修复中使用。

### 4. 路线身份随执行登记

比较实验可同时记录 `declared_route_id` 与 `executed_route_id`。两者不同必须登记
回退原因；发生 fallback 的结果不能冒充原路线的比较证据。旧结果保持兼容，新的
路线比较应通过标准执行器传入路线身份。

### 5. 语义风险由结构触发，反例按单元执行

`question_delta` 仍保留题目继承关系，但不再独占高风险触发权。系统同时从
`coordination`、资源间聚合文本、非联合分解、待比较 endpoint 和显式嵌套量词派生语义风险。一次
全局 `semantic_adversary` 负责独立重建；每个高风险单元仍必须在正式搜索前各自
运行 3--5 个 scorer 语义案例，其中至少一个绑定该单元的排序反例。最终 Red Team
仍只选一个最高价值主攻击，避免恢复成大清单；逐单元反例属于实验完整性，不占用
红队主攻击名额。

## 明确不增加的门禁

- 不为 25 条审计意见分别创建 25 个 hard gate。
- 不把 seed 数、搜索预算、图表数量或文档字段完整度统一写成绝对阈值。
- 不把“有回执/有哈希”视为科学独立性的证明；哈希只证明文件未漂移。
- 不把 sampled scorer 仅靠改名提升为 exact；精确性仍由具体题型 oracle 负责。
- 不让 schema 通过、测试全绿或台账齐全替代路线竞争和独立复算。

## 后续适配原则

搜索健康、目标公平 probe、Excel、图表和 review receipt 不再各自发明生命周期。
它们只需输出真实证据或消费上述状态：发现负证据就调用统一级联，需要关闭科学
修复就绑定验收角色。只有缺失会直接改变正式科学答案、且有确定性验收和可执行
修复路线时，才新增 hard gate。
