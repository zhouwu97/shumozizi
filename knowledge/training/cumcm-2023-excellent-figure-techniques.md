# 2023 年优秀数学建模论文：绘图方法与技巧

## 学习范围与边界

本卡是对已完成学习的 13 篇 2023 年论文中图表设计、绘制和论证方式的二次提炼，重点学习“什么数据用什么图、图上应编码什么机制、如何检查图是否真的支持结论”。样本包括 A092、A127、A165、A175、B226、B311、B477、C050、C126、C235、D039、E032、E176；C228 因 PDF 中文字体映射损坏，无法可靠阅读，不进入图表技法归纳。

这里只迁移图表结构和验证习惯，不迁移原论文的题目参数、数据、结果、代码、图中文字或结论。图表技法是论文表达辅助，不能替代 endpoint 定义、统一评分器、独立复算、留出验证和约束审计。

## 1. 总原则：图先服务主张，再选择图形

一张图至少要有一个明确问题和一个可复述的结论。写图之前先填写：观察对象是什么、横纵坐标的统计单位是什么、颜色/大小/线型分别编码什么、读者应看到哪个阈值或机制、这个观察会改变哪一个决策。若图只重复表格、只展示算法运行过程或无法解释坐标含义，应删除、改图或降为附录。

按论证角色，可把图分成四类：

1. `model_understanding`：定义空间、坐标、事件、流程和问题继承关系；
2. `decisive_evidence`：直接比较 baseline、候选路线、留出误差、约束可行性或最终方案；
3. `insight`：解释边际收益、活跃约束、空间/时间机制和权衡；
4. `stability`：展示采样、随机种子、敏感性、残差、收敛和不确定性，通常适合放在附录或验证小节。

正文 hero 图应承担最关键的一个或两个论证义务，并在图注中写出“观察—机制—决策后果—边界”。不应把三张互不相关的小图拼成一个看似复杂的主图。

## 2. 数据结构到图形的选择表

| 数据/论证对象 | 首选图形 | 必须编码或标注 | 常见误用 |
|---|---|---|---|
| 空间点、有限区域、场值 | 等比例散点、`pcolormesh`/等值线、六边形密度图 | 可行域/禁区、坐标单位、统一色标、采样密度 | 用普通折线或不等比例坐标替代空间图；把插值当作实测 |
| 轨迹、路径、方向和覆盖 | 路径叠加障碍/覆盖热图，必要时加箭头或分段 | 起终点、方向、边界、漏覆盖/重叠、基准路径 | 只画一条中心线，隐藏转弯、不可行段和覆盖缺口 |
| 过程时间、事件、阶段 | 折线、小倍图、事件线、甘特图、阶梯图 | 时间窗、单位、事件/切换点、共享横轴 | 所有对象挤在一张长图；用双纵轴掩盖尺度差异 |
| 实际—拟合—预测 | 三线或点线图 + 预测区间 | 训练/留出切分、预测起点、基线、区间含义 | 只展示训练拟合；没有误差带或留出标记 |
| 分布和偏态 | 直方图 + ECDF、箱线/小提琴图、分位数图 | 样本量、分箱/带宽、异常值处理、单位 | 只报均值；分组样本量差异不标注 |
| 两变量关系 | 散点 + 拟合线/置信带 + 残差图 | 拟合对象、单位、分组、样本量、预测与相关的区别 | 由相关线直接宣称因果或弹性 |
| 多变量相关 | 以零为中心的发散色带热图 | 变量顺序、相关类型、显著性/样本范围 | 彩虹色带；格子太小仍强行标注全部数字 |
| 聚类或分层对象 | 二维投影 + 簇中心/轮廓，或排序热图 | 距离/特征、簇大小、标准化方式 | 只给簇编号表；把聚类编号当作自然类别 |
| 约束下的优化 | 响应面/等值线 + 可行域遮罩；baseline/challenger 点线图；Pareto 图 | 硬约束、基准、最优点、活跃约束、指标方向 | 用算法收敛曲线证明最优；只画目标不画可行性 |
| 排程、容量和状态切换 | 甘特图、阶梯图、占用曲线 | 容量线、切换点、批次/资源、空闲区间 | 只画顺序不画资源占用和瓶颈 |
| 波动、多尺度和监测 | 分解图、时间—尺度热图、尺度方差曲线 | 尺度单位、边界效应、有效区域、监测点/阈值 | 把边界伪影解释成周期；只画系数不说明尺度 |
| 网络、OD 或关联结构 | 过滤后的网络图、邻接热图、流量矩阵 | 节点/边含义、筛选阈值、方向、权重 | 节点过多形成不可读的“毛线团” |

图形选择的核心不是“高级图比基础图好”，而是编码是否与数据结构一致。一个带清晰约束线、留出切分和误差带的普通折线图，往往比没有语义的三维图更有证据价值。

## 3. 可复用的绘制方法

### 3.1 空间场、散点和覆盖图

连续网格数据可用热图、`pcolormesh` 或 `contourf`；不规则采样点可用等比例散点、`tricontourf` 或六边形密度图。绘制前先把禁区和不可行点做成 mask，避免用颜色掩盖硬约束。空间图应固定 `x/y` 比例，统一同一组面板的坐标范围、刻度和色标；颜色表示效率、误差或覆盖值时，色条必须有单位和明确的方向。

离散位置图适合用点、矩形或小圆表示实体，点大小不要同时承载难以解释的第三变量。若需要展示多个效率分量，应采用共享空间底图的多面板，并在面板标题中写出分量和单位；不要让读者靠颜色猜测“颜色越亮是否越好”。密集图可降低点透明度、抽样或分箱，但要报告抽样/分箱规则。

### 3.2 轨迹、方向和几何事件

路径图至少标出起点、终点、方向和不可行区域；连续轨迹可用折线，方向场可用箭头或 `quiver`。如果论点是覆盖质量，路径本身不够，应增加覆盖、漏覆盖和重叠的空间图层，或给出同一网格上的计数/比例图。几何示意图应标记真实对象、辅助线、交点、法向、入射/反射方向以及有限范围；辅助线不能与实体边界使用完全相同的视觉编码。

### 3.3 时间序列、预测和事件

长序列优先使用小倍图、分层聚合或滚动窗口；多个对象共享横轴，避免每个面板重复一套日期标签。预测图使用“实际值—预测值—区间”三层编码，画出预测截止线并同时给自然 baseline。事件、政策、节日、切换或异常点用垂线/标记注明，不能通过事后文字猜测。多尺度或季节分解采用上下排列的共享时间轴；波let/尺度图用 `pcolormesh` 时应标明尺度方向、有效区域和边界效应。

### 3.4 分布、关系和残差

分布图先检查偏态和样本量，再决定是否使用对数或其他变换，并在轴标签中说明。分组比较可用箱线/小提琴图配合原始点或样本量；如果异常值本身有业务含义，不应悄悄删除。散点图可叠加拟合线和置信带，但应配残差图或留出误差，区分相关、预测和因果。相关热图以零为中心；聚类图要让簇规模和特征差异可见。

### 3.5 优化、方案比较和约束

二维决策问题优先用响应面/等值线图，灰色或半透明区域表示不可行域，另用醒目标记显示 baseline、challenger 和最终方案。多指标问题可用配对点线图、误差棒、Pareto 前沿或权衡散点，坐标方向必须统一。若存在容量、预算、服务水平或安全阈值，约束线要直接画在图上，并注明哪个约束在最终方案处活跃。

算法轨迹、温度下降或迭代目标只能说明搜索过程，不等于路线优于 baseline，也不等于全局最优。比较图应来自同一 exact scorer、相同硬约束和可比预算；若展示随机搜索结果，使用箱线图/点云表达多种子分布，而不是只挑一条最好曲线。

### 3.6 排程、容量和状态

批次、设备或人员安排使用甘特图/区间条；资源占用和库存变化使用阶梯图或面积图，并叠加容量线。切换点、空闲区间、等待时间和瓶颈要能从图上定位。若采用分批或递推策略，同时展示单批决策和长周期累计损失/服务水平，避免只给最终总数。

## 4. 版式、标注和输出检查

1. 先以论文最终版面尺寸设定字体、线宽、点大小和图例位置，再导出 PNG/PDF；屏幕上可读不代表缩小到正文栏宽后可读。
2. 同一论证中的面板共享轴范围、单位、色彩语义和图例；只有确有必要时才允许不同尺度，并在标题中说明。
3. 使用色盲友好配色，并做灰度/黑白检查；不要只靠红绿或颜色深浅区分关键类别，应叠加线型、标记或直接标注。
4. 标题说清对象和时间窗，轴标签写单位，图注说清数据来源、聚合、采样、拟合/预测和不确定性。
5. 关键点不靠悬空箭头表达：基准、阈值、切换点、最终方案和异常点应贴近数据并避免遮挡。
6. 多面板图在导出后检查文字越界、图例覆盖数据、色条与面板错位、裁剪、箭头穿字、坐标比例和最小字号。
7. 图必须由当前 `result_id` 和当前脚本重新生成；结果、筛选条件或 endpoint 变化后，旧图不能继续放在 `figures/current/`。

这张表给的是“图形组合的起点”，不是新题的固定模板。应先根据当前题目的空间、集合、时间、网络、场、决策面或区间结构重新选择，并将最终图绑定到当前实验结果。

## 6. 常见误用与负面证据

- 用三维饼图、装饰性透视或过度渐变增加复杂度，却降低类别比较精度；
- 用普通柱形图/折线图作为空间、集合、网络或决策面数据的唯一正文证据；
- 用 dual y-axis 把量纲和尺度差异隐藏起来；
- 只画算法收敛曲线、温度曲线或搜索轨迹，未与统一 baseline 和 exact 指标比较；
- 只画训练拟合，不画时间留出、预测区间、残差或简单基线；
- 只画路线中心线，不画有限覆盖、漏覆盖、重叠、障碍和边界；
- 相关矩阵、灰色关联或趋势相似图被写成因果、弹性或机制证明；
- 图和表使用不同时间窗、样本键、单位或筛选规则；
- 多种子结果只报最好的一次，或通过删掉不稳定结果制造“稳定”；
- 图注只说“如图可知”，没有观察、机制、决策后果和适用边界。

上述误用不是单纯的美观问题：它们会使图表与 endpoint、约束、验证或结果来源脱钩，应按负面证据处理，必要时使图、结论和论文口径一起失效。

## 7. 绘图工作流

1. 冻结图要回答的主张和论证角色；
2. 写数据合同：来源、`result_id`、主键、时间窗、单位、筛选、缺失/异常处理；
3. 选择与数据结构匹配的视觉编码，先画最小可读版本；
4. 在图中加入基准、阈值、约束、事件、方向、区间或有效区域等机制标注；
5. 统一面板范围、色标、图例、字号和版面尺寸，完成彩色与灰度检查；
6. 用当前数据生成 PNG 和 PDF，检查几何一致性、文字越界、遮挡和裁剪；
7. 人工复述图：我看到了什么、为什么会这样、这会改变哪个决策、在哪些条件下不成立；
8. 将图注和结果绑定到当前实验，旧结果、旧脚本或旧 endpoint 变化时重新生成。

## 9. 学习结论

最可迁移的绘图能力不是记住某个库函数，而是把“数据结构—视觉编码—机制标注—验证边界—决策后果”连成闭环。对于数学建模论文，主图应优先帮助读者理解问题、比较方案或解释关键权衡；稳定性和复现细节可以进入附录，但不能被省略。任何图形模板都必须在当前题面、当前 endpoint、当前结果和当前约束下重新核对。
